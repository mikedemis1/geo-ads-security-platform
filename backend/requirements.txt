# Runtime dependencies, pinned deliberately.
#
# These were unpinned until 2026-09-14, which meant CI installed whatever had
# been released that morning while this machine still had older versions. A
# starlette release broke the test suite for three days without a single commit
# being involved. Pinning is what makes a green build still mean something
# tomorrow.
#
# requirements.lock.txt holds the full resolved set including transitive
# packages, and the Dockerfile builds its wheels from it. The two files are
# generated together: change one without the other and the image build fails
# with "No matching distribution", because the wheel directory is installed
# with --no-index.
#
# To upgrade: unpin in a scratch virtualenv, run the suite, and if it is green
# regenerate both files from the same pip freeze.
